# CE 추가 분석 — build 24966116

분석일: 2026-09-19~20. 설치 파일은 읽기만 했다. 게임 실행·메모리 변경·설치본 패치·화면 검증은 수행하지 않았다. 원천, 해제한 데이터와 분석용 실행 파일 코드 조각은 Git 제외 영역에만 보관한다.

## 두 시나리오가 보이지 않았던 이유

파일 부재가 아니라 **기존 파서의 외부 wrapper 미지원**이었다. 한국어와 일본어 설치 파일 모두 존재하며, 시나리오별 DLC app ID를 시드에 사용하는 XOR 변환 뒤에 기존 CE 헤더와 LWC 본문이 나온다.

| 코드 | 한국어 제목 | 시작 | 모드 | 본문 무장 ID | Steam DLC app ID |
|---|---|---|---|---:|---:|
| 32 | 조조의 오산 | 196년 6월 | 일반 | 1,400 | 4598950 |
| 33 | 패기웅심 | 202년 8월 | 일반 | 1,400 | 4598960 |

초기 상태는 `(시나리오 코드 + app ID) mod 2^32`다. 각 바이트에서 `state = state × 0x6c078965 + 0x3039`를 32비트로 제한하고, `((state >> 16) XOR (state >> 24)) AND 255`를 XOR한다. 출력 헤더·버전·파일 코드·LWC 길이·본문 경계·모든 무장 참조를 검증한다. 잘못된 app ID를 넣으면 지원 파일처럼 취급하지 않는다.

[재현 보고서](../reports/dlc-analysis-24966116-r4.json)는 KO/JP 네 파일의 원본/변환/본문 해시와 헤더 교차 대조를 기록한다. 실제 계정 이용권은 설치 manifest와 구별한다. 해독 성공은 계정 소유의 증명이 아니다.

설치 실행 파일의 로더를 정적으로 조사해 상수와 시드 구성을 확인했다. 패킹된 코드 구간의 로컬 분석에는 [Steamless 원저장소](https://github.com/atom0s/Steamless)의 Variant31.x64 형식 설명 코드를 참고했다. 이 연구용 자료·코드 구간·추출 보조물은 배포물에 넣지 않았으며 변경된 실행 파일을 만들거나 실행하지 않았다. 제품 파서는 입력 데이터 wrapper만 처리한다.

## 신분과 모드 정정

`0001_KO/msgdata_exce.bin`의 zp1 블록과 UTF-16 메시지 테이블에서 독립 enum을 찾았다. 메시지 249~258은 `무효, 군주, 도독, 태수, 일반, 재야, 포로, 미등장, 미발견, 사망` 순서다.

- raw 5: 종전 ‘확인 중’ → **재야**
- raw 6: **포로**. 현재 초기 시나리오에 관측되지 않아도 enum은 보존한다.
- raw 8: 종전 ‘재야’ → **미발견**
- raw 9: ‘사망·은퇴’ → **사망**

군주·도독·태수·일반은 검색에서 ‘현역’으로 묶고 원래 raw 값은 보존한다. 모드 메시지 4~8에서 일반/튜토리얼/체험판/전기제패의 코드 순서를 교차 확인했다. 시나리오 52개 중 일반 39개, 전기 10개, 튜토리얼 3개이며 일반 무장 탐색은 39개에 제공한다.

## 정책 구성 참조와 레벨 수치

정책 레코드의 8개 구성 슬롯은 다른 정책이 아니라 **정책 효과 ID**를 가리킨다. 종전 연결을 수정했다. 예를 들어 문사무비의 구성 ID 10, 11, 12, 13, 39, 42는 사기 상한·군량 소비·수송·지원 시설·도시 내구·건설 속도 효과다.

공통 본문 section 26, offset 324181에는 134바이트 × 101행의 효과 테이블이 있다. 이름 22바이트, 설명 92바이트, 마지막 20바이트에 1~10레벨 값이 있다. 레벨 조회 함수의 정적 분석에서도 인덱스가 1~10에 대응하는 것을 확인했다. 효과 13·14·24는 설명에 시설/함선 개방 레벨이 들어 있으므로 기본 수치 벡터를 실제 수치 효과로 표시하지 않는다.

동일 발동 효과에 해당하는 정책은 레벨 합계를 사용한다는 점은 [CE 공식 설명서](https://www.gamecity.ne.jp/manual/sangokushi14-pk/ce/jp/4100.html)와 일치한다. 이 앱은 현재 세력의 배치 상태를 읽지 않으므로 개인 정책 레벨을 실제 세력 효과로 자동 환산하지 않는다.

효과 조회 함수와 호출부를 추적해 백분율, 정수 가산, 개방 전용 효과를 구분했다. 실행 파일의 기본 계수는 해당 원본 바이트 위치에서 다시 검증한다. 신분·모드 메시지와 달리 단위는 **실행 코드의 산술 흐름을 해석한 근거**다. 사기 상한은 기본값 100과 계수 1 조건에서 가산 값으로 표시하고, 내구는 점수, 명령서는 개수, 그 밖의 수치 효과는 기본 백분율로 구분한다. 근거 위치와 실행 파일 해시는 [정책 의미 보고서](../reports/policy-semantics-24966116-r4.json)에 기록했다.

이 표는 게임 기본 계수의 정적 참조다. 저장 게임의 설정 변경, 개성·방책 등 추가 보정, 적용 대상별 상한·반올림을 모두 계산하는 시뮬레이터가 아니다. 복합 정책의 최종 효과를 단순 덧셈하지 않는다.

## 무장 분류의 의미

프로필에 원천 ID 범위와 실제 레코드 인덱스 구간을 명시하고 모든 시나리오에서 검사한다. 기본 1,000개와 추가 88개의 대응 열전 메시지도 대조한다. 추가 무장 2078~2082는 원천 열전이 빈 문자열이므로 프로필에 예외와 사유를 기록했으며, 명시적인 ID/슬롯 구간을 분류 근거로 사용한다. 열전을 만들어 채우지 않는다. UI 명칭은 ‘기본 무장’과 ‘추가 무장’이다. 내부 호환용 `HISTORICAL` 키가 모든 인물의 역사적 실존을 보증하는 것은 아니다. NPC·예약 슬롯·계정 이용권은 별도 개념이다.

기존 50개 시나리오의 70,000행에는 신분 라벨 23,775건 외의 예기치 않은 변경이 없었다. 이 비교와 동일 파서 전수 대조는 ETL 손실 검사이며 게임 화면 검증으로 바꾸어 기록하지 않는다.
