# CE 검증과 출시 판정

상태는 `PASS`, `UNRESOLVED`, `EXCLUDED_BY_USER`, `MISSING`, `STALE_OR_MISSING_LINEAGE`로 구별한다. 화면 제외는 자동 검사 성공과 합산하지 않는다.

`web/release_gate.py`를 API·DB 검증·패키지 검사에서 함께 사용한다. DB의 `release_ready=1` 설정과 blocker 문자열 삭제만으로 승격할 수 없다. 필수 근거가 없거나 계보가 다르면 공개 handler는 503 점검 응답을 유지한다.

| 범위 | 근거 | 현재 판정 |
|---|---|---|
| G1 원천·DLC | inventory, KO/JP wrapper 보고서, 52개 본문 | 해독·참조 검사 완료 |
| G2 신분·모드 | 별도 메시지 enum과 레코드 raw 코드 | 교차 대조 완료 |
| G2 무장 분류 | ID/슬롯 구간·열전 메시지 | 원천 그룹 확인; 역사성·이용권 판정과 구분 |
| G2 정책 정량 | 효과 ID 연결, 10단계 원천 값, 개방 조건 | 기본 계수의 단위·개방 조건 대조 완료; 진행 게임의 동적 효과 계산은 제공하지 않음 |
| G2 ETL | 후보 SHA가 일치하는 원천 전수 대조·diff | 후보마다 새 보고서 필요 |
| G3 API·DOM | 합성 계약 + 실제 후보 통합 검사 | 후보마다 새 보고서 필요 |
| G3 화면·실기기 | 사용자 지시 | EXCLUDED_BY_USER |
| G4 재현·패키지 | 같은 코드 SHA의 두 빌드, 허용 목록/해시/복원 | 후보마다 새 보고서 필요 |
| G4 원격 운영 | 보호 정책·원격 HTTP·복구·관찰 | 미실행 |
| 공개 수용 | 구체적 후보·범위에 대한 결정 | 미확정 |

자동 검사와 공개 승격은 별개다. `scripts/run_checks.py --database ...`는 실제 후보가 없거나 통합 검사가 skip되면 통과하지 않는다. DB가 없는 복제본의 기본 검사는 합성 계약을 수행하고 실제 게임 통합 검사 제외 사유를 기록한다.

원천·프로필·파서·Git SHA가 달라지면 이전 후보 보고서는 현재 후보의 출시 근거가 아니다. `reports/completion-24966116-r4.json`이 생성되면 그 보고서의 링크와 해시를 최종 자동 검사 기준으로 사용한다. 정식 배포를 수행하지 않았으면 배포 ID, 복구 완료, 공개 후 1시간/다음 날 관찰을 완료로 적지 않는다.
