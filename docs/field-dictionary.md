incoming은 같은 시나리오의 outgoing 간선을 역방향 조회한 결과다. 친애·혐오·혼인은 상대의 레코드에 없는 역방향을 만들지 않는다. 의형제만 명시적인 그룹 키로 그룹 구성원 사이의 양방향 간선을 파생하며 원천 그룹 키를 별도 보존한다. 데이터가 빈 시나리오를 다른 시나리오로 대체하지 않는다. 관계의 type·source·target·slot과 레코드 위치를 보존한다.

공통 사전의 section ID·record count·offset·stride는 `profiles/ce-ko-24966116.json`에 기록했다. 도시 52슬롯 이후 관문 10개를 전역 거점 ID 52~61로 연결한다. 개성·진형·주의·정책 설명은 원문 텍스트로 추출했다. 정책 레코드 +136~143의 8바이트 ID 배열은 구성 정책 연결이다. 문사무비(47)는 10/11/12/13/39/42를 참조한다. 레벨별 정량 효과 공식은 아직 해석하지 않았으며 계산하지 않는다. 전법은 보유 관계와 이름을 제공하고 효과 설명 결측을 구분한다. 공통 사전의 임시 명칭(예: ‘정책’) 슬롯은 원천 DB에는 보존하되 도감에서 제외한다.

내면 인코딩은 [원 작성자의 레코드 분석 699번](https://medaka.5ch.io/test/read.cgi/gamehis/1585043390/699)과 CE 원천 70,000행을 교차 확인했다. `value = 3 + raw / 10`, 상태는 `CROSS_CHECKED`이며 게임 화면 검증을 뜻하는 `VERIFIED`와 구분한다. 350,000개 필드의 부호 있는 raw 값·절대 offset·인코딩을 `personality_evidence`에 보존한다. +171~175의 값은 능력 상한 보정값이므로 내면으로 사용하지 않는다. 표본: ce-05 조조 의리 2/외교 3/한조 3/야망 5/호전 4, 관우 의리 5.

시나리오 헤더는 원본 파일 기준 title +422(34바이트 UTF-16LE), year +456(u16), mode +458(u8), month +461(u8), code +462(u16)이다. 파일명 code와 헤더 code 불일치, 알 수 없는 버전, 참조 범위 이탈, 해제 길이 오류는 빌드를 중단한다.

`verify_source.py`는 50개 시나리오에서 ID 집합, 정규화 필드, 내면 값과 위치 증거, 혼인·의형제 키, 개성·진형·전법 slot, 관계 방향·target·slot, 사전 설명·정책 구성요소를 전수 대조한다. 파서와 같은 형식 가설을 사용하므로 잘못된 의미를 함께 재현할 가능성은 남는다. 게임·웹 화면 검증은 사용자 요청으로 이번 작업에서 제외했다.
